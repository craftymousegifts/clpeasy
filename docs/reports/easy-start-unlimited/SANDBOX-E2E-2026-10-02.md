## Findings
- **Duplicate-check insert can fail on a cold start** (existing behaviour, not caused by this
  change).
  - The `invoice.created` delivery on the first cold start hit "JWT issued at future" (PGRST303)
    on its duplicate-check insert.
  - The function correctly falls through and processes the event (it ignores non-renewal
    invoices), but that event id is not recorded, so a redelivery of that event wouldn't be
    de-duplicated.
  - Harmless for `invoice.created` / `invoice.paid` (both write absolute values). It would only
    matter for a PAYG credit event on such a cold start.
  - Recorded; not changed.
- **QA data:** the 2 QA users, 2 Sandbox customers and 2 Sandbox subscriptions (both now ended) are
  left in place as evidence.
