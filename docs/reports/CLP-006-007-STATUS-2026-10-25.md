## 9. Step 4 typing delay on iPhone Safari (25 Oct 2026, fix `374dd45`)

**Report (Michaela, real iPhone Safari, FRAG0019):** extraction worked. In Step 4, letters typed into the business website appeared very slowly. Safari did not freeze.

**Cause (confirmed):**
- The website field has no validation. Like every Step 4 field, each key runs one `updateLabel()` (one label render) plus `saveBizDetails()`. The handler is identical on main.
- When the label does not fit its size, `updateLabel()` also ran `findSmallestFittingSize()` on every key, re-rendering the label at up to ~100 candidate sizes for the "Needs X mm" advice. Most of that time was `measureText`.
- The long FRAG0019 supplier wording on a 63 mm circle does not fit, so every key paid for the search.

**Main vs #270:** the problem exists on main (it is not a regression). #270 is slower per key and reaches it more often, because supplier-faithful wording is longer.

Per-key blocking, FRAG0019 on a 63 mm circle, iPhone 13 viewport (Chromium emulation):

| Build | Desktop CPU (median) | 4× CPU throttle (median) |
|---|---|---|
| main `d51ddb3` | 1.1 s | 5.0 s |
| #270 before fix | 1.7 s | not captured |
| #270 with `374dd45` | 0.03 s | 0.10 s |

A fitting label (square 90 mm) took about 30 ms per key on every build.

**Netlify preview toolbar:** it does not contribute.
- On the deployed preview, typing with the toolbar loaded and with it hidden took 1.60 s and 1.61 s per key.
- The toolbar used no script time while idle.
- Its only effect is that it covers the mobile Next button (preview links only).

**Fix (`374dd45`, 2 files):**
1. `label-render.js`: measured text widths are memoised (generic system fonts only, so a cached width cannot go stale). Label output is unchanged; the full suites below pass.
2. `builder.html`: while a field is typed in (an `input` event), the fit advice and size search are refreshed once typing pauses (400 ms) instead of on every key.
   - The download block (`_labelBlockDownload`, `toggleDownload()`) is still recalculated on every key.
   - After the pause, the advice equals a full synchronous recalculation (checked: "Needs 71 mm", same HTML, same block state).

**Verification:**
- `npm test`: exit 0 (Deno edge-function tests SKIPPED, not installed).
- `npm run test:sds-faithful`: exit 0.
- Supplier wording and CLP-005/006/007 behaviour are unchanged: the same suites that cover them pass.
- Typing timed at iPhone 13 size for guest and account, circle 63 mm / square 90 mm / rectangle 90 mm. The website value was stored correctly and there were no page errors.
- Preview `deploy-preview-270` has served `374dd45` since 22:23 UTC on 25 Oct (Netlify status). Tests made before then used the slow build.

**Remaining per-key cost after the fix:**
- At 4× throttle: about 45 ms of main-thread work per key for a paid account, and about 115 ms for guest/trial users.
- The extra for guest/trial users is the watermarked preview: an SVG → 520×520 PNG conversion per key, plus, for signed-in users without a paid plan, one Supabase profile read per key.
- This is pre-existing (identical on main). It is recorded here, not changed.
- I also tried merging overlapping preview conversions. It gave no measurable gain (17 keys still produced 17 conversions at 12× throttle), so it was reverted and not committed.

### Release notes (for the release record)
